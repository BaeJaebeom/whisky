# 위스키 노트 설계

## 목적

PC에서 쓰는 개인 위스키 리뷰 블로그. 글과 사진 정도만 들어가는 단순한 사이트.
다른 컴퓨터에서는 GitHub 웹에서 리뷰 폴더를 올리는 것만으로 글을 추가할 수 있어야 한다.

## 결정 사항

| 항목 | 결정 |
|---|---|
| 도구 | Hugo (로컬 v0.169.0), 테마 없이 직접 만든 레이아웃 |
| 호스팅 | GitHub Pages 프로젝트 사이트 `https://<계정>.github.io/whisky/` |
| 배포 | Hugo 공식 GitHub Actions 워크플로, main push 시 자동 배포 |
| 분류 | `content/` 아래 폴더 = 분류. 지금은 대분류만(scotch, irish, american) |
| 리뷰 주소 | 폴더 경로를 그대로 따름 (`/whisky/scotch/glenfiddich-12/`) |
| 사진 | 본문에 `![](파일명)`으로 적은 사진만 표시, 대표 사진은 `cover.*`. 사이트에는 줄인 사진만 내보내고 원본·안 쓴 파일은 내보내지 않는다(`publishResources = false`) |
| 검색 | Pagefind (배포 때 리뷰 화면을 색인). 입력하는 즉시 본문 자리에 결과 표시 |
| 정보 표 | 글 front matter 에 적은 순서 그대로, 빈 줄마다 구분선. 원문 파일을 직접 읽어 만든다 |
| 태그 | Hugo taxonomy `태그`. 태그 페이지 `/tags/<태그>/`, 메뉴 아래 태그 모음 |
| 자바스크립트 | 검색에만 사용 |

## 폴더 구조

```text
content/
├── _index.md                 # title: 전체
├── scotch/
│   ├── _index.md             # title: 스카치 위스키, weight: 1
│   ├── glenfiddich-12/index.md
│   ├── johnnie-walker-black-label-12/index.md
│   └── jura-12/index.md
├── irish/
│   ├── _index.md             # title: 아이리시 위스키, weight: 2
│   └── jameson-original/index.md
└── american/
    ├── _index.md             # title: 아메리칸 위스키, weight: 3
    └── buffalo-trace/index.md
```

분류 폴더의 `_index.md`에는 한글 이름(`title`)과 메뉴 순서(`weight`)를 적는다.
중분류·소분류는 같은 방식으로 하위 폴더를 만들면 된다. 레이아웃은 깊이에 상관없이 동작해야 한다.

## 리뷰 양식

Front matter 키는 사용자가 쓰던 한글 항목 이름을 그대로 쓴다. 제품명은 `title`, 작성일은 `date`.
`type`은 Hugo 예약어라서 쓰지 않고 `타입`으로 쓴다.

```yaml
---
draft: true
title: 글렌피딕 12년
date: 2026-11-04
태그: [셰리, 버번]

카테고리: 스카치 위스키
타입: 싱글 몰트
지역: Speyside
증류소: 글렌피딕 증류소

매시빌: 몰트 100%
증류: 팟 스틸 2회 증류
캐스크: 버번 + 올로로소 셰리
숙성: 12년

도수: 40%
용량: 700ml
색소: O
칠필터링: O

가격:
구매처:
구매일:
---

## 노즈

## 팔레트

## 피니시
```

- `카테고리`는 글마다 직접 적는 항목이다. 왼쪽 메뉴의 분류(폴더)와는 별개이며, 폴더 경로는 위치 표시와 검색에만 쓴다.
- `title`, `date`, `draft`, `태그` 외의 줄은 모두 정보 표 항목이다. 항목 이름과 순서, 묶음은 글마다 자유롭다. 단 Hugo 예약 영어 키(`description`, `summary`, `weight`, `aliases`, `url`, `slug`, `type`, `layout` 등)는 표에서 뺀다(`info-groups.html`의 `$skip`).
- `태그`는 `[셰리, 버번]`처럼 YAML 목록으로 적는다. 대괄호 없이 쉼표가 든 글자로 적거나, 태그 이름 안에 쉼표가 있으면 빌드를 멈춘다(태그 하나로 묶이거나 주소 `?tags=`에서 쪼개지는 실수 방지).
- 서로 다른 태그가 같은 주소가 되면(`40%`와 `40` → `/tags/40/`) 빌드를 멈춘다(`tag-check.html`).
- `date`가 없으면 빌드를 멈춘다. 예약 발행이 없으므로 미래 날짜 글도 바로 공개한다(`buildFuture = true`).
- 새 글은 `draft: true`로 시작한다. 지우면 공개된다.
- 값에 ` #`이나 `: `가 들어가면 큰따옴표로 감싼다(YAML 주석·키로 해석되기 때문). 값으로 `-` 하나만 적으면 YAML 목록 기호로 읽혀 빌드가 실패하므로 비워 둔다.

## 화면

### 공통

- 위쪽 사이트 제목 없음. 왼쪽 메뉴(240px)와 오른쪽 본문만 있다. 사이트 이름 "위스키 노트"는 브라우저 탭 제목에만 쓴다.
- 메뉴, 목록, 리뷰는 각각 테두리·그림자 있는 패널(`#313337`)에 담아, 배경(`#27292c`)과 구분한다. 리뷰 하나는 패널 하나다.
- 720px 이하에서는 메뉴 패널이 본문 위로 올라간다.
- 차콜 톤 다크 테마, 회색 구분선, 로즈 강조색(`#fb7185`) 하나, 시스템 글꼴. 강조된 항목의 글자(현재 분류·태그와 그 숫자, 검색 결과에서 걸린 단어)는 대비 4.5:1을 넘도록 더 밝은 로즈(`#fda4af`)를 쓴다.
- 마우스를 올렸을 때는 메뉴 항목과 목록 줄 모두 같은 회색 바탕(`#3d3f44`)만 바뀐다. 그 바탕 위 흐린 글자(날짜·캐스크 · 도수·글 수 등)는 대비 4.5:1을 넘도록 조금 밝은 회색(`#aeaba7`)이 된다. 강조색은 "지금 위치"(현재 분류, 현재 페이지 번호)에만 쓴다. 현재 쪽 번호는 마우스를 올려도 강조색을 유지한다.
- 없는 주소는 404 화면(`layouts/404.html`)을 보여 준다. 사이드바와 검색이 그대로 있다.

### 왼쪽 메뉴

- 맨 위 검색창, 구분선, 그 아래 `전체 (N)`, 그 아래 분류 트리.
- 각 분류 옆 괄호는 하위 분류까지 포함한 공개 글 수. 공개 글이 없는 분류는 숨긴다.
- 하위 분류가 있는 분류는 `<details>`로 열고 닫는다. 지금 보고 있는 페이지가 속한 줄기는 열린 채로 그린다.
- 분류 이름을 누르면 그 분류 화면으로 이동한다.
- 지금 보고 있는 분류(리뷰 화면이면 그 리뷰가 속한 분류)를 강조색 글자와 옅은 강조색 바탕으로 표시한다.
- 메뉴 항목은 둥근 칸이다.
- 하위 분류 화살표는 26×30px 영역 전체가 눌린다. 화살표는 열고 닫기만 하고, 분류 이름은 이동한다.
- 분류 트리 아래 구분선, 그 아래 태그 모음(제목 글자 없이 태그만). 글이 많은 태그부터 나열하고, 4단계(13·14·16·19px, 흐림→밝음)로 크기와 밝기를 달리한다. 단계는 "서로 다른 글 수"의 순위로 나눈다(글 수가 같으면 같은 단계). 30개까지 보여 주고, 넘으면 "모든 태그 (N)" 링크(`/tags/`).
- 태그 모음의 태그는 누르면 고르고 다시 누르면 푼다(검색 참고). 고른 태그는 강조색. 새 탭으로 열면(⌘·Ctrl 클릭) 태그 화면으로 간다.
- 메뉴가 화면보다 길어지면 메뉴 안에서 스크롤한다.

### 태그 화면

- `/tags/<태그>/`: 분류 화면과 같은 목록 패널. 제목은 `#셰리 5`, 위치 표시 `전체 › 태그`, 10개씩 나눈다.
- `/tags/`: 모든 태그 모음.

### 목록 (첫 화면, 분류 화면)

- 목록 전체가 패널 안에 들어간다. 검색 결과도 같은 패널 모양.
- 위치 표시(분류 화면만), 제목과 글 수. 제목 아래 구분선.
- 한 줄에 글 하나, 작성일 최신순. 상위 분류는 하위 분류 글까지 포함한다. 줄 사이 구분선.
- 줄 높이는 사진 유무와 상관없이 84px로 고정한다. 제목과 줄 정보가 길면 말줄임표로 자른다.
- 줄 구성: 왼쪽 56px 정사각 썸네일(대표 사진이 있을 때만, 없으면 사진 자리 없이 글자부터), 제목, 그 아래 `캐스크 · 도수` 값(글에 적은 값, 빈 값은 뺌), 작성일.
- 글이 없으면 "아직 글이 없습니다."
- 한 쪽에 10개씩 나눈다. 목록 아래에 `‹ 1 … 5 6 7 8 9 … 13 ›`처럼 첫 쪽, 마지막 쪽, 지금 쪽 앞뒤 2쪽만 번호를 보이고 사이는 `…`로 줄인다. 2쪽부터 주소는 `…/page/2/`. 한 쪽뿐이면 번호를 그리지 않는다.
- 검색 결과도 같은 모양으로 10개씩 나눈다(주소의 `page=`).

### 리뷰 화면

- 패널 하나에 위치 표시(전체 › 스카치 위스키), 제목, 작성일, 태그(`#셰리` 칩, 누르면 태그 화면), 대표 사진(있으면, 높이 480px 이하), 한 톤 어두운 칸에 든 정보 표, 본문 순서로 담는다. 글 파일의 첫 묶음(`draft`·`title`·`date`·`태그`)과 같은 순서로 위에 모은다.
- 정보 표는 글 front matter 에 적은 순서 그대로이고, 빈 줄마다 묶음(구분선)을 나눈다.
  - Hugo 는 front matter 의 순서와 빈 줄을 버리므로 `os.ReadFile`로 원문을 읽어 줄 단위로 나눈다(`layouts/_partials/info-groups.html`). 글마다 `partialCached`로 한 번만 읽고, 정보 표와 목록 줄이 같은 결과를 쓴다.
  - 들여쓴 줄, `-`·`#`로 시작하는 줄, `:`이 없는 줄은 항목이 아니다. `"인용 키"`처럼 따옴표로 감싼 키는 따옴표를 뗀다.
  - `os.ReadFile`은 프로젝트 폴더 밖 파일을 빈 값으로 돌려주므로, front matter 를 읽지 못하면 빌드를 멈춘다.
- 값: 없거나 빈 값은 흐린 `—`. 숫자·참거짓은 Hugo 가 바꾸지 않게 적은 글자 그대로(`43.0`, `0`, `false`, 뒤의 `# 주석`은 뺌). 날짜로 해석된 값은 `2026-11-01` 형태. 목록은 쉼표로 잇는다. 여러 줄 묶음(map)은 빌드를 멈춘다.
- 본문 소제목(노즈·팔레트·피니시)은 본문(16px)보다 큰 19px 강조색 글자. 소제목 사이에 구분선은 없고 간격만 둔다.

## 사진

- 리뷰 폴더 안에 둔다(페이지 번들).
- 본문 사진: `![](glass.jpg)`을 적은 자리에 나온다. 긴 변 1600px 이하로 줄이고 EXIF 방향을 반영한다.
- 대표 사진: 이름이 `cover.*`인 파일. 목록 썸네일(160×160 가운데 자르기, `cover-thumb.html` 한 곳에서 만듦)과 리뷰 화면 위(긴 변 1200px 이하)에 나온다.
- 방향 맞추기와 크기 조절은 `.Filter images.AutoOrient (images.Process "…")`로 한 번에 해서 한 번만 인코딩한다.
- 원본과 본문에 안 쓴 파일은 사이트에 내보내지 않는다. 줄인 사진에는 EXIF(위치 정보 포함)가 남지 않는다. 단 저장소가 공개이므로 원본은 GitHub에서 받을 수 있다(README에 위치 정보를 지우고 올리라고 안내).
- 본문에 적은 사진이 폴더에 없거나, 줄일 수 없는 형식(HEIC 등)이면 빌드를 실패시키고 파일 경로를 알려 준다.
- 외부 주소(`https://…`) 이미지는 그대로 보여 준다.

## 검색과 태그 거르기

조건 세 가지를 모두(AND) 만족하는 글을 본문 자리의 "검색 결과" 패널에 보여 준다.

- **범위:** 분류 화면이면 그 분류(하위 분류 포함) 안, 그 밖의 화면이면 전체.
- **태그:** 사이드바에서 고른 태그가 모두 달린 글. 태그 화면(`/tags/셰리/`)에서는 그 태그를 고른 채로 시작한다.
- **검색어:** 왼쪽 검색창. Pagefind 규칙을 따른다. 띄어 쓴 단어가 모두 들어 있는 글, 단어 앞부분 일치(계피 → 계피맛), 단어 가운데 글자로는 못 찾음(로소 ✗ 올로로소), 영문 대소문자 무시. 맞는 단어가 없으면 앞부분이 비슷한 단어로도 찾는다(없는단어 → 없는듯). 한국어 형태소 분석 없음.

동작:

- 조건이 지금 화면 그대로(검색어 없음, 태그는 그 화면 기본값)면 원래 화면을 보여 주고, 하나라도 다르면 결과 패널로 바꾼다. 입력·클릭 즉시 바뀐다.
- 결과 패널 위에 검색어와 고른 태그를 칩으로 보여 준다(범위는 보여 주지 않는다). 칩의 ×로 하나씩 빼고, "모두 해제"는 그 화면의 원래 상태로 돌아간다(태그 화면이면 그 태그만 고른 상태).
- 결과는 목록 줄과 같은 모양, 10개씩 나누고 번호 규칙은 목록과 같다.
  - 검색어가 있으면 Pagefind 관련도순(제목·메타데이터에 든 글이 위). 태그·분류만이면 작성일 최신순.
  - 검색어가 있고 본문에서 걸렸으면 제목 아래 줄에 "캐스크 · 도수" 대신 걸린 문장(excerpt, 두 줄까지, 검색어는 강조색)을 보여 준다. 걸린 단어 앞은 4단어만 남기고 `…`로 줄여서 좁은 화면에서도 걸린 단어가 보이게 한다. 제목·태그·분류 이름에서만 걸렸으면 "캐스크 · 도수"를 그대로 둔다.
- 조건은 주소에 남긴다: `?q=바닐라&tags=셰리,버번&page=2`. 태그는 쉼표로 잇는다. 주소로 열면 같은 결과를 그린다. 기록은 `replaceState`로 바꿔서 뒤로 가기가 쌓이지 않는다.
- 조건이 있는 동안 분류 메뉴 링크에 `q`·`tags`를 붙여서, 분류를 바꾸면 그 분류 안에서 다시 거른다.
- 검색창 오른쪽 지우기(×) 버튼, Esc로 검색어만 지운다.
- 자바스크립트가 꺼져 있으면 태그는 태그 화면 링크로 동작한다. 켜져 있으면 사이드바 태그에 `role="button"`·`aria-pressed`를 붙이고 Space 로도 누를 수 있다.
- 키보드로 쪽 번호나 칩을 누르면 포커스를 지금 쪽 번호·남은 칩(없으면 검색창)으로 옮긴다. 결과 수와 상태는 화면 밖 `#search-announce`(aria-live)로 읽어 준다.

데이터 (Pagefind 1.6.0):

- 배포 워크플로가 `hugo build` 다음에 `npx pagefind --site public`을 실행해 `public/pagefind/`에 색인을 만든다. `hugo server` 미리보기에는 색인이 없어서 검색하면 "검색을 불러오지 못했습니다" 안내가 나온다.
- 색인 대상은 리뷰 화면의 `<article data-pagefind-body>` 안뿐이다. 사이드바·목록·태그 화면은 색인하지 않는다(모든 화면에 있는 태그 모음 때문에 모든 글이 걸리는 것을 막는다).
- 그 안에서도 위치 표시·제목·작성일·태그 칩은 `data-pagefind-ignore`로 본문 색인에서 뺀다. 걸린 문장에 섞이지 않게 하기 위해서다. 제목은 Pagefind 가 자동으로 메타 `title`로 잡고, 태그·분류 이름은 아래 메타로 넣어 계속 검색된다.
- `layouts/page.html`에서 붙이는 값:
  - 필터 `tag`: 소문자로 맞춘 태그. 화면은 고른 태그를 소문자로 바꿔 넘긴다(`Sherry`=`sherry`). 여러 개면 모두 해당(AND).
  - 필터 `section`: 글이 속한 분류 주소들. 분류 화면 범위에 쓴다.
  - 정렬 `date`: 작성일. 검색어 없이 태그·분류만 거를 때 최신순으로 쓴다.
  - 메타 `date`, `tags`(태그 이름), `path`(분류 이름), `line`(캐스크 · 도수), `thumb`(썸네일 파일 이름만), `image`(빈 값). 메타데이터도 검색되므로 썸네일은 주소 전체 대신 파일 이름만 넣고, Pagefind 가 본문 첫 사진 주소를 자동으로 넣는 `image`는 빈 값으로 덮는다("whisky", "scotch"로 사진 있는 글만 걸리던 문제).
- 결과는 전체 개수만 먼저 받고, 보여 줄 10개분만 `data()`로 받는다. 글이 많아져도 필요한 색인 조각만 받는다.
- Pagefind 웹 워커는 시험 환경에서 색인을 못 읽어서(`Failed to load Pagefind metadata`) `noWorker: true`로 메인 스레드에서 돈다.
- 입력이 빠르게 이어질 때 늦게 온 이전 결과가 덮어쓰지 않도록 마지막 요청 결과만 그린다.
- 주소(`replaceState`)는 입력이 0.3초 멈췄을 때 한 번만 바꾸고, 같은 주소면 건너뛰고, 오류는 무시한다. 페이지를 떠날 때(`pagehide`) 마지막으로 쓴다. Safari(WebKit)는 10초에 100번 넘게 바꾸면 오류를 내서 검색까지 멈췄기 때문이다.
- 불러오기·검색·결과 받기(`data()`)에 실패하면 결과를 비우고 안내를 보여 주며, Pagefind 인스턴스를 버려(`destroy`) 다음 동작 때 처음부터 다시 준비한다. Pagefind 의 `init()`은 색인을 못 받아도 실패로 끝나지 않기 때문이다.

## 배포

- `.github/workflows/hugo.yaml`: 공식 워크플로에서 쓰지 않는 Dart Sass·Go·Node 설치 단계를 뺀 것. Hugo 버전 고정, `TZ=Asia/Seoul`. 빌드 뒤 Pagefind(버전 고정)로 검색 색인을 만든다(러너에 기본 설치된 Node의 `npx` 사용).
- 권한: 워크플로 기본은 `contents: read`. build 단계는 `contents: read`·`pages: read`(Pages 설정 읽기)만, deploy 단계만 `pages: write`·`id-token: write`. build 단계에서 npx 로 받은 외부 코드가 돌기 때문이다.
- 사용자가 할 일: GitHub에 공개 저장소 `whisky`를 빈 상태로 만들기 → Settings → Pages → Source를 GitHub Actions로 → push.

## 검증

- `hugo build`가 경고 없이 끝난다.
- 브라우저: 목록, 메뉴 글 수, 분류 화면, 리뷰 정보 표(적은 순서·빈 줄 묶음), 태그 칩·태그 화면·태그 모음, 대표 사진, 본문 사진, 검색(태그 포함), 좁은 화면.
- 임시 중분류 폴더: ▸ 메뉴가 생기고, 상위 분류에 하위 글이 포함되고, 주소가 폴더 경로를 따른다. 확인 후 되돌린다.
- 없는 사진 이름, HEIC 파일, 날짜 없음, 여러 줄 묶음 값, 태그 속 쉼표, 주소가 겹치는 태그 → 빌드 실패.
- 사이트에 원본 사진·안 쓴 파일이 없고, 세로 사진(EXIF 회전)이 바르게 나온다.
- Safari(WebKit)에서 빠르게 쳐도 칩·결과·주소가 같다. 검색 색인을 못 받았다가 되찾으면 같은 탭에서 다시 검색된다.
- 초안 없이 빌드하면 초안이 빠진다.
