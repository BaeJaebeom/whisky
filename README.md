# 위스키 노트

Hugo로 만든 위스키 리뷰 블로그. `main`에 push하면 GitHub Actions가 빌드해서 GitHub Pages에 올린다.

## 한눈에 보기

```text
content/
├── _index.md                       ← "전체" (건드리지 않음)
├── scotch/                         ← 대분류 폴더
│   ├── _index.md                   ← 메뉴 이름·순서
│   ├── johnnie-walker-black-label-12/
│   │   └── index.md                ← 리뷰 한 편
│   └── single-malt/                ← 중분류 폴더 (필요할 때 만듦)
│       ├── _index.md
│       └── glenfiddich-12/
│           ├── index.md
│           ├── cover.jpg           ← 대표 사진 (없어도 됨)
│           └── glass.jpg           ← 본문 사진 (없어도 됨)
├── irish/
└── american/
```

- 리뷰 한 편 = 폴더 하나. 폴더 안에 `index.md`와 사진을 둔다.
- 왼쪽 메뉴는 `content/` 아래 폴더 구조 그대로 그려진다.
- 리뷰 주소도 폴더 경로를 따른다. 예: `/whisky/scotch/single-malt/glenfiddich-12/`

## 글 쓰기

1. **리뷰 폴더 만들기.** 넣을 분류 폴더(예: `content/scotch/`) 안에 리뷰 폴더를 만든다. 이름은 영어 소문자와 `-`만 쓴다. 이 이름이 주소가 된다. 예: `glenfiddich-15`
2. **`index.md` 만들기.** 아래 [양식](#양식)을 복사해 리뷰 폴더 안에 `index.md`로 저장한다. `title`, `date`, `태그`와 항목을 채우고, `## 노즈` 같은 소제목 아래에 느낀 점을 쓴다.
3. **사진 넣기 (선택).** 사진을 같은 폴더에 넣는다. 대표 사진은 이름을 `cover.jpg`로 하고, 본문 사진은 넣을 자리에 `![잔에 따른 모습](glass.jpg)`을 적는다. 자세한 건 [사진](#사진).
4. **공개하기.** 다 썼으면 `draft: true` 줄을 지운다. 이 줄이 남아 있으면 올려도 공개 사이트에 나오지 않는다.
5. **올리기.** 리뷰 폴더를 커밋한 뒤 `main`에 push한다. GitHub 웹에서 올릴 때는 저장소의 분류 폴더로 들어가 **Add file → Upload files**에 리뷰 폴더를 통째로 끌어다 놓고, **Commit directly to the main branch**로 커밋한다.
6. **확인하기.** 1~2분 뒤 저장소 **Actions** 탭에 초록 체크가 뜨면 사이트에 반영된 것이다. 빨간 X면 로그에 어떤 파일이 문제인지 나온다(양식 오타, 없는 사진 이름, 대괄호 없는 태그 등). 이때 사이트는 직전 상태 그대로다.

알아 둘 것:

- **미리보기:** Hugo가 설치된 컴퓨터라면 저장소 폴더에서 `hugo server -D`를 실행하고 http://localhost:1313/whisky/ 에서 미리 볼 수 있다. 초안(`draft: true`)도 보인다. 검색은 배포할 때 색인을 만들기 때문에 미리보기에서는 동작하지 않는다.
- **브라우저에서 바로 쓰기:** GitHub 저장소 화면에서 `.`을 누르면 브라우저용 VS Code(github.dev)가 열린다. 거기서 폴더와 파일을 만들고 바로 커밋해도 된다.
- **여러 곳에서 쓸 때:** 로컬 저장소에서 쓰기 전에 먼저 pull을 받는다. 다른 곳에서 올린 글을 받지 않고 push하면 충돌이 난다.

## 양식

```markdown
---
draft: true
title: 글렌피딕 12년
date: 2026-11-04
태그: [셰리, 버번]

카테고리: 스카치 위스키
타입: 싱글 몰트
지역: Speyside
증류소: 글렌피딕 증류소

매시빌:
증류:
캐스크:
숙성:

도수:
용량:
색소:
칠필터링:

가격:
구매처:
구매일:
---

## 노즈

## 팔레트

## 피니시
```

| 항목 | 뜻 | 화면에 나오는 곳 |
|---|---|---|
| `title` | 제품명 | 목록 제목, 리뷰 제목 |
| `date` | 작성일 (`2026-11-04` 형식). 꼭 적는다(없으면 빌드 실패). 미래 날짜도 바로 공개된다 | 목록 오른쪽, 리뷰 제목 아래. 목록은 이 날짜 최신순 |
| `draft: true` | 초안 표시. 이 줄이 있으면 공개 사이트에 안 나온다 | 미리보기에서만 보임 |
| `태그` | 검색·모아 보기용 꼬리표 | 리뷰 제목 아래, 왼쪽 메뉴의 태그 모음 |
| 나머지 항목 | 정보 표 항목 | 리뷰의 정보 표. `캐스크`와 `도수`는 목록 제목 아래에도 나온다 |

### 정보 표

- 적은 순서 그대로 표에 나온다. 빈 줄을 넣은 자리에 구분선이 생긴다. 위 양식이면 네 묶음으로 나뉜다.
- 항목은 자유롭게 더하거나 빼도 된다. `나이테: 12개`처럼 새 줄을 적으면 그대로 표에 한 줄 생긴다.
- 항목 이름에는 `:`을 쓰지 않는다. 줄 맨 앞을 띄어 쓰거나 `-`, `#`으로 시작하면 표에 안 나온다.
- 값을 비워 두면 표에 `—`로 나온다. 모르는 값은 비워 둔다. `가격: -`처럼 `-` 하나만 적으면 목록 기호로 읽혀 빌드가 실패한다. 꼭 적고 싶으면 `가격: "-"`처럼 따옴표로 감싼다.
- 숫자나 `0`, `false`도 적은 그대로 나온다(`도수: 43.0` → 43.0).
- 값은 한 줄로 적는다. 아래 줄에 들여 써서 여러 줄 묶음으로 적으면 빌드가 실패한다. 여러 개는 `향: [바닐라, 꿀]`처럼 대괄호로 적는다.
- 값에 ` #`이나 `: `가 들어가면 큰따옴표로 감싼다. 예: `매시빌: "옥수수 (Mash Bill #1)"`
- `카테고리`는 글마다 직접 적는다. 왼쪽 메뉴의 분류(폴더)와는 따로다.
- 목록 제목 아래 줄은 `캐스크`와 `도수` 값을 쓴다. 이 두 이름을 바꾸면 그 줄에서 빠진다.
- `title`, `date`, `draft`, `태그`는 이름 그대로 둔다. 이 넷은 표에 나오지 않는다.
- `description`, `summary`, `weight`, `aliases`, `url` 같은 영어 이름은 Hugo가 따로 쓰는 이름이라 표에 나오지 않고 사이트 동작을 바꿀 수 있다. 정보 표 항목은 한글로 적는다.

### 태그

- `태그: [셰리, 버번, 스모키]`처럼 대괄호 안에 쉼표로 적는다. 대괄호를 빼면 빌드가 실패하고 Actions 로그에 그 글이 나온다.
- 태그 이름에는 쉼표를 쓸 수 없다(빌드 실패).
- `%` 같은 기호는 주소에서 빠진다. 그래서 `40%`와 `40`처럼 기호만 다른 태그는 주소가 같아져 빌드가 실패한다. 이럴 땐 한쪽 이름을 바꾼다.
- 태그도 검색된다. 본문에 `Sherry`라고 썼어도 태그에 `셰리`를 넣으면 "셰리"로 찾을 수 있다.
- 왼쪽 메뉴의 태그 모음은 글이 많이 달린 태그부터, 많을수록 크게 나온다(30개까지, 넘으면 "모든 태그" 링크).
- 리뷰 제목 아래 태그를 누르면 그 태그가 달린 글 목록(`/whisky/tags/셰리/`)으로 간다.
- 영문은 대소문자를 구분하지 않는다(`Sherry`와 `sherry`는 같은 태그). 띄어쓰기가 있으면 주소에서 `-`로 바뀐다.
- 태그가 없으면 `태그: []`로 두거나 줄을 지운다.

### 검색과 태그 거르기

- 왼쪽 메뉴의 태그를 누르면 고르고, 다시 누르면 푼다. 여러 개 고르면 고른 태그가 **모두** 달린 글만 나온다.
- 검색창에 글자를 치면 그 조건도 같이 걸린다. 띄어 쓴 단어는 모두 들어 있어야 한다.
- 검색어는 단어 앞부분으로 찾는다. "계피"로 "계피맛"은 찾지만, "로소"로 "올로로소"처럼 단어 가운데 글자로는 못 찾는다. 맞는 단어가 없으면 앞부분이 비슷한 단어로 찾기도 한다.
- 분류 화면(예: 스카치 위스키)에서 고르면 그 분류 안에서만 찾는다. 태그를 고른 채로 분류 메뉴를 누르면 조건을 들고 그 분류로 간다.
- 결과 위의 `#셰리 ×`처럼 조건을 하나씩 빼거나 "모두 해제"로 원래 화면으로 돌아간다(태그 화면에서는 그 태그만 고른 상태로). 결과는 10개씩 나뉜다.
- 검색어가 있으면 더 잘 맞는 글(제목에 들어간 글 등)이 위에 오고, 제목 아래에 검색어가 걸린 문장이 나온다. 태그·분류만 고르면 작성일 최신순이고 제목 아래는 "캐스크 · 도수"다.
- 조건은 주소에 남는다. 예: `/whisky/scotch/?q=바닐라&tags=셰리,버번` — 즐겨찾기하거나 보내면 같은 결과가 열린다.

### 본문

`---` 아래가 본문이다.

- `## `로 시작하는 줄은 소제목이다(강조색으로 크게 나온다). `## 총평`처럼 더 만들어도 된다.
- 문단은 빈 줄로 나눈다. 줄만 바꾸면 한 문단으로 붙는다.
- 사진은 `![설명](파일이름)` 한 줄.

```markdown
## 노즈

서양배와 바닐라 향이 먼저 올라온다.
시간이 지나면 셰리의 건포도 향.

![잔에 따른 모습](glass.jpg)

## 총평

데일리로 무난하다.
```

## 사진

- 본문에 넣을 자리에 `![설명](glass.jpg)`을 적는다. 적은 사진만 나온다.
- 이름이 `cover`인 사진(`cover.jpg` 등)은 목록 썸네일과 리뷰 맨 위에 나온다.
- JPG, PNG, WebP만 된다. HEIC는 JPG로 바꿔서 올린다.
- 사이트에는 빌드할 때 웹용으로 줄인 사진만 공개된다. 원본과 본문에 안 쓴 파일은 사이트에 올라가지 않고, 줄인 사진에는 위치 정보(EXIF)가 남지 않는다.
- **단, 저장소는 공개라서 올린 원본은 GitHub에서 누구나 받을 수 있다.** 휴대폰 사진의 위치 정보는 올리기 전에 지운다(아이폰: 사진 공유 → 옵션 → 위치 끄기).
- 원본은 저장소에 그대로 쌓인다. 긴 변 2000px 정도로 줄여서 올린다(맥: 미리보기 → 도구 → 크기 조절).
- 적은 사진이 폴더에 없거나 형식이 맞지 않으면 빌드가 실패한다. 사이트는 직전 상태로 남고, Actions 로그에 파일 경로가 나온다.

## 분류 (대분류·중분류·소분류)

분류 = `content/` 아래 폴더. 폴더마다 메뉴에 보일 이름을 적은 `_index.md`가 있다.

```markdown
---
title: 싱글 몰트
weight: 1
---
```

- `title`: 메뉴에 보일 이름
- `weight`: 같은 단계 안에서의 메뉴 순서(작을수록 위). 같은 숫자면 최근 글이 있는 분류가 위로 와서 글을 올릴 때마다 순서가 바뀔 수 있으니, 분류마다 다른 숫자를 쓴다.

### 대분류 만들기

`content/` 안에 폴더를 만들고(예: `japanese`), 그 안에 `_index.md`를 만들어 `title: 일본 위스키`, `weight: 4`를 적는다. 그 안에 리뷰 폴더를 넣으면 메뉴에 나온다.

### 중분류·소분류 만들기

분류 폴더 안에 폴더를 하나 더 만든다. 깊이 제한은 없다.

1. 분류 폴더 안에 하위 폴더를 만들고(예: `content/scotch/single-malt`), 그 안에 `_index.md`를 만들어 `title: 싱글 몰트`, `weight: 1`을 적는다.
2. 이미 쓴 글이면 리뷰 폴더를 그 하위 폴더 안으로 옮긴다. 새 글이면 처음부터 그 하위 폴더 안에 리뷰 폴더를 만든다.
3. 소분류도 같은 방식으로 한 단계 더 만든다(예: `content/scotch/single-malt/speyside`).

알아 둘 것:

- 하위 분류가 생기면 메뉴의 상위 분류 옆에 화살표가 붙는다. 화살표를 누르면 열리고 닫히고, 이름을 누르면 그 분류 글 목록으로 간다.
- 상위 분류를 누르면 하위 분류 글까지 모두 나온다. 괄호 안 숫자도 하위 글까지 센다.
- 공개된 글이 하나도 없는 분류는 메뉴에 안 나온다.
- 글을 다른 분류로 옮기면 주소가 바뀐다(예: `/whisky/scotch/glenfiddich-12/` → `/whisky/scotch/single-malt/glenfiddich-12/`). 예전 주소로 공유한 링크는 열리지 않는다.
- 폴더 옮기기는 GitHub 웹에서는 번거로우니 로컬 저장소에서 옮긴 뒤 커밋하고 push하는 편이 편하다.
